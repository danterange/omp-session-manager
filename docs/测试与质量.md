# 测试与质量

## 测试层级

| 层级 | 范围 | 执行方式 |
| --- | --- | --- |
| Unit | 参数解析、搜索、窗口匹配、OMP 可执行文件定位等无真实用户数据的规则。 | `TestCategory=Unit` |
| Integration | 隔离临时目录中的 JSONL 扫描、索引保存/重载和异常字段兼容。 | `TestCategory=Integration` |
| UI smoke | STA 线程中的主窗体构造和稳定 automation name。不会显示窗体、扫描真实会话或写入默认索引。 | `TestCategory=UI` |
| 手工 UI 验收 | 使用虚构 JSONL 在真实 Windows 桌面验证搜索、标签、筛选、详情与截图。 | `scripts/Start-Demo.ps1` |
| 发布验证 | 隐私扫描、格式、Release build、无 PDB publish、安装包、ZIP 和 SHA-256。 | 发布脚本 |

UI smoke 不等同于完整端到端 UI 自动化。涉及 MessageBox、恢复外部 OMP 进程和安装器的流程，必须在隔离演示数据下进行相称的手工验收；不要在测试中恢复真实会话。

## 本机质量门禁

```powershell
pwsh -NoLogo -NoProfile -File .\scripts\Invoke-QualityGate.ps1
```

该命令依次执行：

1. 发布候选内容的高置信度隐私扫描；
2. `dotnet restore`；
3. 两个项目的 `dotnet format --verify-no-changes`；
4. Release build 且将 warning 视为 error；
5. Unit、Integration 与 UI smoke 测试；
6. self-contained single-file `win-x64` publish；
7. 发布目录检查：应用 EXE 存在、没有 PDB、FileVersion 与唯一版本来源一致、没有高置信度敏感模式。

在非交互 CI 环境中使用 `-SkipUi -SkipPublish`，但不能将跳过的 UI 或发布验证标记为已通过。

## GitHub Actions

`.github/workflows/quality.yml` 在推送到 `main` 或针对 `main` 的 Pull Request 时执行非交互质量门禁。它不生成 Release，也不替代版本发布前的本机安装包验证。

## 当前验证基线

本次公开发布准备中，测试项目包含 Unit、Integration 与 UI smoke 覆盖。每次打包必须重新执行命令并以本次输出为准；历史记录中的测试次数或日期不能替代当前验证证据。
