# 测试计划

## 自动化检查

| 类型 | 命令或入口 | 目标 |
| --- | --- | --- |
| 隐私扫描 | `scripts/Test-PublicReleaseContent.ps1` | 当前候选文件的密钥、邮箱和用户目录高置信度模式。 |
| 历史隐私扫描 | 加 `-IncludeGitHistory` | 可达提交身份、提交信息和文件内容。 |
| 格式 | `dotnet format ... --verify-no-changes` | 与仓库格式器一致。 |
| Release build | `dotnet build ... --configuration Release --warnaserror` | 编译和 warning 零容忍。 |
| Unit | `TestCategory=Unit` | 参数、搜索、窗口匹配和路径定位规则。 |
| Integration | `TestCategory=Integration` | 临时 JSONL、索引持久化与数据兼容。 |
| UI smoke | `TestCategory=UI` | STA 主窗体构造及 automation name。 |
| 发布物 | `Test-ReleaseArtifact.ps1` | EXE、FileVersion、PDB 和敏感模式。 |

## 手工验收

1. 用 `scripts/Start-Demo.ps1` 打开完全虚构的演示会话。
2. 确认列表、搜索、筛选、详情、标签按钮和状态栏清晰可用。
3. 仅截取应用窗口；检查截图中没有任务栏、账户、用户路径或真实会话。
4. 生成 installer 后验证文件存在、哈希可计算、安装目录含主 EXE；如执行安装测试，必须使用隔离临时目录。

## 验收原则

- 每次 Release 重跑所有适用检查；过去的测试次数不构成当前证据。
- 在非交互 CI 跳过 UI 或发布构建时，报告应明确为“未执行”，不能写为通过。
- 不在测试中启动或恢复真实 OMP 会话。
