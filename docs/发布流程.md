# 发布流程

## 版本来源

`Directory.Build.props` 中的 `<Version>` 是唯一版本来源。版本使用 `MAJOR.MINOR.PATCH` 语义化格式；预发布版本可使用例如 `1.1.0-rc.1`。

更新版本：

```powershell
pwsh -NoLogo -NoProfile -File .\scripts\Set-ProjectVersion.ps1 -Version 1.0.1
```

不要在 `.csproj`、installer、README、zip 文件名或 tag 中手工复制版本号。发布脚本将同一参数传递给这些位置，并在 publish 后读取 EXE 的 FileVersion 进行校验。

## 发布前清单

1. 所有功能与文档修改已完成，README 的中文和 English 内容一致。
2. `CHANGELOG.md` 已记录该版本的用户可见变更。
3. UI 截图仅含虚构演示数据，已检查图片元数据和可见区域。
4. 当前分支为 `main`，工作区中没有无关改动。
5. `gh auth status` 成功，且当前身份具有目标仓库的发布权限。
6. 运行可达历史扫描：

   ```powershell
   pwsh -NoLogo -NoProfile -File .\scripts\Test-PublicReleaseContent.ps1 -IncludeGitHistory
   ```

## 一键发布

```powershell
pwsh -NoLogo -NoProfile -File .\scripts\Publish-GitHubRelease.ps1 -Version 1.0.0
```

该脚本会：

1. 更新 `Directory.Build.props` 的唯一版本值；
2. 运行隐私扫描、代码格式、Release build、Unit/Integration/UI smoke tests；
3. 发布 self-contained、single-file 的 `win-x64` 输出，关闭调试符号；
4. 扫描发布目录，确认没有 PDB、绝对用户目录、高置信度私钥或常见 token，并核对 EXE FileVersion；
5. 用 Inno Setup 生成 per-user installer，生成 portable ZIP 和每个资产的 SHA-256 文件；
6. 暂存全部变更后，再次扫描 staged 发布候选和可达历史；
7. 创建本地 commit、annotated tag、推送 `main` 和 tag；
8. 创建 GitHub Release、上传四个资产，并回读资产列表验证上传完整性。

当前依赖本机 Inno Setup 6 的 `ISCC.exe`。若编译器、GitHub CLI 登录、`main` 分支、版本 tag 或任何质量检查不满足，脚本会停止，不会假装发布成功。

如果 `main` 和同名 tag 已成功推送、但创建或上传 GitHub Release 时中断，请先确认 `main` HEAD 与 tag 指向同一提交且工作区干净，再运行：

```powershell
pwsh -NoLogo -NoProfile -File .\scripts\Publish-GitHubRelease.ps1 -Version 1.0.0 -Resume
```

`-Resume` 不会创建第二个 commit 或 tag；它会重新构建资产并创建/补传 Release，然后重做远端 SHA-256 校验。

## 发布资产

- `OmpSessionManager-Setup-<版本>.exe`：per-user Windows 安装程序。
- `OmpSessionManager-Setup-<版本>.exe.sha256`：安装程序 SHA-256。
- `OmpSessionManager-<版本>-win-x64-portable.zip`：解压即用的便携版。
- `OmpSessionManager-<版本>-win-x64-portable.zip.sha256`：便携版 SHA-256。

## 发布后验收

1. 查看 GitHub Release 是否包含四个资产，名称和 tag 是否一致。
2. 下载一个资产并用 `Get-FileHash` 与 `.sha256` 比较。
3. 在干净或隔离环境中安装/解压并启动应用；不要用真实 profile 做截图。
4. 通过 `scripts/Start-Demo.ps1` 或等效启动参数检查界面、版本和基本搜索流程。
5. 如需撤回，先停止分发并创建说明性修复 Release；不要通过重写已公开的正常发布历史掩盖问题。若包含敏感数据，按 GitHub 的敏感数据清理流程处理。
